# 2.99.0.1 适配说明

构建入口仅接受 SHA-256 为 `0db34e19d9eeb6d496d20fabe786ec16bbd36ba6b0ccdc8d29cb7e909c114397` 的官方 2.99.0.1 程序，原件不得原地覆盖。r5 成品 SHA-256 为 `8befb2376c0bf941688819b6fde31afcf760525f115dc4767120977e8acbba04`。

r5 将独立安装器的版本清单、候选源和文件传输接到真实 PCL 原生 API，复用其 Mojang/BMCLAPI 调度、设置、并发、限速、分段和重试。移除自建 HTTP 引擎；共享依赖直接使用最终路径，失败时保留完成文件。适配前后检查原生下载 API 及内嵌 FileChecker，不兼容则保留旧版。具体调用和验证见 [pcl-download.md](pcl-download.md)。

- 将 `PageDownloadInstall.LoaderInit` 接回原有 Minecraft 版本列表加载器，并恢复原版下载导航。
- 仅在新建安装页隐藏组件组合并清空组件选择；不对继承的已安装版本修改页应用该限制。保留整合包限制。
- 保持 `ModLaunch`、`PageDownloadModify`、`ModModpack` 及其嵌套方法体和官方 OAuth Client ID；使用既有正版会话进行启动验证。
- 将全局缓存、启动环境 TEMP/TMP、任务临时目录和组件资源目录定向到 EXE 同目录的 PCL。保留启动清理同步逻辑，删除外部 ProgramData 清理分支；路径不满足上游组件要求时提示移动目录。
- 官方更新方法改为调用内嵌更新模块。r3 查询官方仓库最新正式版包，下载后在本机适配和验证，再由系统 PowerShell 替换原路径 EXE；原包、完整候选使用 .bin，备份使用 .bak；取消 Latest.exe 副本及系统临时目录回退。
- 新增共用的 net8/net48 AdaptationCore。关键方法的兼容性契约允许版本字符串和构建号变化，结构变化时拒绝自动恢复；登录和组件管理的方法体在每次适配前后比较。恢复后的成品继续携带下一代适配引擎。
- 在 EXE 中嵌入更新模块、适配引擎、dnlib 元数据读取器及许可；只在内存加载这些固定依赖。未完成适配与验证的官方原包不执行。官方重打包但无需更新时记住已核对提交，避免重复提示。
- 更新模块与适配引擎不生成携带本地路径的调试记录；发布文件重新扫描已知个人信息和测试会话标识。
- r4 增加独立原版下载引擎与主窗口入口：直接处理 Mojang 清单、客户端、Windows 依赖/原生库、资源索引、旧版资源映射和日志配置；生成标准版本文件及纯原版组件清单。支持搜索、类别筛选、指定目录/名称、取消及已完成依赖校验复用。
- r4 将原下载页兼容性与基础接入契约分开。原下载页变化时，可在基础接入通过后使用 independent 模式；基础接入不兼容则仍保留旧版。独立引擎传递给下一代，后续可恢复 native 模式。
- 同盘安装整体发布完成目录；跨盘独占创建目标并跟踪清理自己的文件，完成后需刷新版本列表。已有同名版本拒绝覆盖，暂存不回退系统目录。
- 保留原作者、赞助和正版购买提示，添加第三方名称和源码地址。每个修改方法的原始特征记录在嵌入的 `PCLRestore.Profile.json`，最终成品哈希记录在稳定更新清单中。

r1 在发布验证中暴露 CLR 反射校验对特殊程序集身份及重复加载的限制，已撤回为草稿。r2 使用元数据读取器修正此问题。r3 增加官方原包本地自动恢复，r4 增加独立下载备用引擎，r5 改用 PCL 原生下载。旧 r2 可通过既有适配通道升级；r3/r4 用户需手动下载 r5 获取本次修改，之后正常更新继续跟随官方仓库。
