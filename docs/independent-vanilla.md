# 原位置静默备用恢复（r6）

r6 删除 r4/r5 的右下角按钮、独立下载窗口和自建安装器。正常模式及备用模式均使用 PCL 原下载标签、原版卡片、名称输入、开始下载按钮、任务列表和安装实现，用户无需选择下载方式。

## 何时接管

| 官方候选变化 | 处理 |
| --- | --- |
| 原下载页关键逻辑仍兼容 | 直接恢复新版原页面，记录 native |
| 关键页面逻辑变化，但页面成员、依赖和原有资源兼容 | 从当前可用 EXE 移植已验证的原生下载页面代码，记录 native-fallback |
| 页面成员/界面资源/依赖或基础接入不兼容 | 拒绝更新，保留当前可用 EXE |

备用过程在安装官方更新前完成，沿用原位置和原生流程，不在运行时弹出第二个窗口。它处理的是页面恢复兼容性，不把普通断网或源站故障当成切换另一套安装器的信号；网络重试/切源仍由 PCL 自己处理。

## 恢复内容与约束

供体为用户当前的已适配 EXE，复制 `PageDownloadInstall`、`PageDownloadLeft` 及其嵌套类型的方法体。页面类型、字段、方法结构必须一致；原有 `.g.resources` 与 `PCL.Resources.resources` 字节必须一致，保证原生控件/BAML 与内嵌组件匹配。这个资源检查比较保守，资源变化也会保留旧版，而不是猜测兼容。

所有本地类型、字段、方法和泛型成员重新映射到候选程序集，并核对签名、成员属性与基类/接口。代码只引用候选当前定义，不引用旧 EXE。输出写出后重新读取，验证每个复制方法与供体一致，验证原生清单、原版导航、纯原版限制及 `ModDownloadLib.McInstallStart` 调用。替换前的方法特征记入适配记录。

正常及备用成品都继承适配引擎，下一次仍可恢复；新版重新满足直接恢复条件时回到 native。未知未来结构不保证兼容。新建安装仅限纯原版，已安装版本的组件管理、登录、原 Client ID 和整合包限制保持原有保护。

安装任务、元数据、资源规则、目录、取消和文件复用采用 PCL 原生实现。缓存和更新事务仍使用已便携化的 `ExeDir/PCL`；游戏输出为选定游戏目录。只分发一个 EXE，不附带用户数据。

实际正常/合成备用页面验收见 [verification.md](verification.md)，用户步骤见 [acceptance.md](acceptance.md)。合成备用样本仅模拟页面方法变化，不代表已验证未来官方版本。
