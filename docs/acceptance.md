# 用户验收步骤

只分发 Release 中的 `PCL-Vanilla-Restore-*.exe`。不要打包运行后生成的 `PCL`、`.minecraft`、日志、设置或备份，它们可能含收件人的账号缓存、路径和启动参数。

1. **干净目录启动**：在可写的英文、无空格目录只放一个 EXE，例如 `D:/Games/PCLRestore/Launcher.exe`。启动后应正常出现窗口；不需要另放 DLL、SDK 或配置文件。运行产生 `PCL` 文件夹是正常现象。
2. **原版下载**：在下载页打开原版游戏，分别选正式版、预览版及较旧版本。新建页应只有名称和原版下载，不能组合 Forge/Fabric 等组件。实际安装一个版本，任务成功后应出现在启动页。
   r6 不应出现右下角独立按钮或另一个下载窗口。备用恢复也应仍使用同一下载页、卡片、名称输入和原生任务列表。在 PCL 设置中可分别测试版本列表/文件源“官方优先”和“镜像优先”；测试后恢复自己的设置。线程和限速沿用原设置。
3. **正版启动**：自行完成微软授权，启动自己拥有的游戏版本。关闭重开后确认账号可用；会话过期时确认正常刷新。项目此前只验证了已有有效正版会话，新授权和强制刷新需用户验收。
4. **已有版本组件**：在隔离游戏目录对一个兼容版本添加 Fabric 等组件，更新组件，再移除；每一步完成后确认版本仍能识别，移除后回到原版。先备份自己的游戏数据。
5. **移动与改名**：退出后把整个测试目录移到另一个盘，并重命名 EXE，再从其它工作目录启动。默认测试游戏目录应仍在当前目录；自行添加的外部游戏路径可能按原设置保存。部分上游组件要求英文或无空格路径。
6. **检查更新**：关于页点击检查更新，当前没有官方更新时应提示最新。官方有新正式版时确认更新；程序应先下载原包并适配，再退出、替换、重启。原生页面不能直接恢复时，应在原下载位置静默接回已验证的原生流程，不能增加单独入口；若页面、资源或基础依赖也不兼容，必须保留当前可用版本。不能安装未恢复下载或缺少更新模块的官方原包。
7. **更新文件与游戏保留**：检查 `PCL/Cache/Update/update.log` 是否记录成功，`adaptation.json` 是否有源提交和输入/输出哈希，旧版是否保存为 `previous.bak`。确认存档、资源包和已有版本还在。更新过程不应出现 `Latest.exe` 或第二个临时 PCL EXE。
8. **其它电脑**：把原始发布 EXE 单独复制到另一台符合 PCL/.NET Framework 4.8 要求的 Windows 电脑，重复启动、下载、正版启动和检查更新。没有完成此项之前，不把本机路径测试等同于跨电脑验收。

损坏包、结构不兼容、锁冲突和失败回退已有自动化夹具覆盖，不建议通过改动自己的生产启动器或账号缓存来制造故障。需要复现时使用独立测试目录和测试世界。请勿公开含账号缓存或完整启动命令的日志。
